Key Concepts

Building blocks

⚡
LLM API Call
A model is stateless. Send a messages array, get back a completion. Text in, text out — every time from scratch.
🔧
Tool Calling
Pass a tools list with JSON schemas. The model returns a structured tool_call instead of prose. Your code runs the function and returns the result.
💬
Message History
State lives in your harness, not the model. Append every turn to a messages list and re-send the whole list on each call.
🪟
Context Window
LLMs have a finite context (~200k–1M tokens). Input tokens are cheaper than output tokens. Providers cache unchanged prefixes — keep early messages stable.
🖥️
Bash as a Tool
Almost all knowledge work is text. The terminal is a text interface to your computer. Give the model a run_bash tool and it can read, write, run, and fetch anything — with your permissions.
🔁
The Agent Loop
A while loop: call LLM → if tool calls, execute them and append results → repeat until no tool calls remain. That's it. That's Claude Code.

The Heart of Every Agent

The ReAct loop

ReAct = Reason → Act → Observe → Repeat. The model reasons, picks a tool, your harness runs it, the result goes back. That's the backbone of Claude Code, Codex, OpenClaw — all of them.
01
Think
Model reads messages, reasons about what to do next.
02
Call Tool
Model returns a structured tool_call instead of prose.
03
Execute
Harness runs the tool (e.g. bash command) and captures output.
04
Observe
Tool result appended to messages. Loop repeats until no more calls.
simple_agent.py — the loop (core) 
for _ in range(MAX_TURNS):
    model_reply = llm_call(messages)          # 1. Think
    messages.append(model_reply)

    tool_calls = model_reply.get("tool_calls") or []
    if not tool_calls:
        typer.echo(model_reply.get("content"))  # done
        return

    for tool_call in tool_calls:              # 2–3. Call & execute
        tool_result = run_bash(
            json.loads(tool_call["function"]["arguments"])["command"]
        )
        messages.append({                       # 4. Observe
            "role":        "tool",
            "tool_call_id": tool_call["id"],
            "content":     tool_result,
        })

Full implementation in src/simple_agent.py — 120 lines total. That's all of it. Everything else in production harnesses is infrastructure to make this loop robust, safe, and ergonomic.

Workshop Examples

Run the scripts

llm_call.py Step 1
uv run python src/llm_call.py "What is a coding harness?"
One LLM request via OpenRouter. Stateless — no memory, no tools.
llm_tool_call.py Step 2
uv run python src/llm_tool_call.py "What is the weather in Munich?"
Model calls a weather tool. Harness fetches wttr.in and returns the result.
llm_multiturn.py Step 3
uv run python src/llm_multiturn.py
Multi-turn chat. State lives in the growing messages list, not the model.
simple_agent.py Step 4
uv run python src/simple_agent.py "List the Python files in src."
Full agent loop with a Bash tool. Asks for confirmation before each command.
simple_agent_interactive.py Step 5
uv run python src/simple_agent_interactive.py
Same agent, persistent conversation history across turns.
dungeon_agent.py Bonus
uv run python src/dungeon_agent.py
A dungeon-crawler agent — tools for moving, fighting, and exploring rooms.
Warning — the agent runs bash commands with your user permissions. Review every command before confirming. Never run untrusted prompts against it.
